# Review and verification

Read-only unless a separate implementation request authorizes an in-scope fix. Inspect the complete staged, unstaged, and untracked diff; project rules; relevant tests; and security-sensitive paths. Apply `security.md`. Review correctness, regressions, scope, tests, maintainability, and relevant security/privacy risks. Report findings by severity with file/line evidence, then validation performed and limits. Do not approve, merge, commit, push, close, or silently repair changes. See `execution.md` for stage criteria and completion gates.
